## 1. 시스템 개요

천장에 거치한 2축 Pan-Tilt 유닛이 1D 라이다를 회전시키며 실내를 훑어 **구면 격자 형태의
3D 포인트클라우드**를 만든다. 이 포인트클라우드가 Edge AI CCTV의 2D 영상과 매칭되어
**마커리스 외부 캘리브레이션**의 입력이 된다.

```
   ┌──────────────┐   UART 115200    ┌──────────────┐
   │   STM32F401  │◄────────────────►│  RPi 4       │
   │              │  protocol.h      │              │
   │  모터 2축    │                  │ /dev/turret  │  ← 커널 드라이버
   │  엔코더 2개  │                  │      ↕       │
   │  라이다 1개  │                  │  adts_daemon │  ← 유저 데몬
   └──────────────┘                  └──────────────┘
          │                                  │
     실시간 제어                       산출물 (.json / .pcd)
     (스텝 펄스, 100Hz 라이다)              │
                                            ▼
                                     카메라 단 캘리브레이션
```

**역할 분리의 원칙**: 지연이 크고 실시간 제어가 어려운 RPi 커널은 UART 바이트 수신·버퍼링만
한다. 스텝 펄스 생성과 라이다 프레임 파싱처럼 마이크로초 단위가 중요한 일은 전부 STM32가
전담한다. 좌표 해석·격자 배치·파일 산출은 RPi 유저 데몬이 한다.

## 3. 좌표계 — 기구각과 계약각

이 프로젝트에서 각도는 **두 가지**가 있고, 둘을 혼동하면 산출물의 절반이 180° 틀린 자리에
박힌다. 가장 먼저 이해해야 하는 개념이다.

### 3.1 기구각 (mechanism angle)

모터/엔코더가 실제로 보고하는 값. "팬 모터가 30° 위치에 있고 틸트 모터가 −45° 기울어
있다." STM32가 아는 것은 이것뿐이며, `protocol.h`가 나르는 값도 전부 기구각이다.

### 3.2 계약각 (contract angle)

빔이 공간상 어느 방향을 보는지. 카메라팀과 합의한 좌표계 기준이고, JSON/PCD에 나가는 값이다.

### 3.3 왜 다른가 — 스윕이 바닥을 넘어가기 때문

기구 틸트의 영점은 **바닥(nadir)**이다. 팬 모터를 30°에 세워두고 틸트만 −90 → +90으로
훑으면:

```
             틸트 -90        틸트 0        틸트 +90
                │              │              │
   벽 A ────────┤              │              ├──────── 벽 B
    (방위 30)   │              │              │  (방위 210)
                └──────────┐   │   ┌──────────┘
                           └───┴───┘
                            바닥
```

| 기구 틸트 | 빔이 실제로 보는 곳 | 계약 pan | 계약 tilt |
|---|---|---|---|
| −90 | 방위 30 쪽 수평 | 30 | 0 |
| −45 | 방위 30 쪽 45° 아래 | 30 | −45 |
| 0 | 똑바로 아래 (바닥) | 30 | −90 |
| +45 | **방위 210** 쪽 45° 아래 | **210** | −45 |
| +90 | 방위 210 쪽 수평 | **210** | 0 |

**팬 모터는 30°에서 한 번도 움직이지 않았는데 빔은 방위 30과 210을 둘 다 훑었다.**
이것이 기구 팬을 180°만 돌려도 계약 방위가 360° 채워지는 이유이자, 라이다 케이블이
감기지 않는 이유다.

### 3.4 변환식

```c
/* daemon/core/scan_output.c : mech_to_contract() */
if (mech_tilt <= 0) {
    pan  = mech_pan;              tilt = -900 - mech_tilt;   /* 벽 A 쪽 반 */
} else {
    pan  = mech_pan + 1800;       tilt = -900 + mech_tilt;   /* 벽 B 쪽 반 */
}
pan %= 3600;   /* 랩어라운드 */
```

검산: m=−900 → (p, 0) 벽 A 수평 / m=0 → (p, −900) 바닥 / m=+900 → (p+1800, 0) 벽 B 수평.

### 3.5 계약 좌표계 (lidar_scan)

```
+x: right   +y: down   +z: forward
pan positive: right    tilt positive: up

x =  range · cos(tilt) · sin(pan)
y = -range · sin(tilt)
z =  range · cos(tilt) · cos(pan)
```

**센서 높이는 좌표에 적용하지 않는다.** frame 이름이 `lidar_scan`이면 원점이 라이다
자신이므로 tilt=0인 점의 y는 0이어야 한다. 높이는 `scan.sensor_height_m` 메타데이터로만
전달한다. (2026-07-29에 실제로 높이를 좌표에 빼서 모든 y가 −1.2m로 찍힌 적이 있고, 그건
사실상 actuator_base 좌표라 라벨과 불일치였다)

### 3.6 계층 분리

| 계층 | 다루는 각도 | 이유 |
|---|---|---|
| STM32 펌웨어 | 기구각만 | 좌표계를 몰라도 됨 → 펌웨어가 단순해지고, 좌표 규약이 바뀌어도 펌웨어를 안 건드림 |
| 커널 드라이버 | 변환 없음 (통과) | 얇은 드라이버 원칙 |
| RPi 데몬 | 기구각 → 계약각 | 기구 배치가 바뀌면 `mech_to_contract()` 한 함수만 고치면 됨 |

## 4. 왜 격자(organized grid)인가

### 4.1 격자 간격의 근거 — 빔 FOV

격자 간격을 정하는 것은 모터 분해능이 아니라 **라이다 빔의 발산각(FOV 1~2°)**이다.

스텝을 FOV보다 잘게 쪼개면 인접 측정이 물리적으로 같은 영역을 본다. 겹침 비율은
`1 − 스텝/FOV`이고 **거리와 무관**하다. 0.1° 스텝이면 겹침이 95%로, 새 정보 없이 데이터만
10배 늘어난다. 1° 스텝이면 겹침 50%로 적정하다.

> 현행은 0.9°다 — 모터 분해능이 아니라 **샘플 간격**에 맞춘 값이다.

### 4.2 organized = 각도 2D 배열 (3D 복셀이 아님)

격자는 3차원 공간을 임의로 나눈 것이 아니라, **(방위 × 고각)의 2차원 배열**이다. 각 칸에
그 방향의 거리 하나가 들어간다 — 이른바 range image다.

```
        방위(계약 pan) 0° ──────────────────────────► 359°
고각  ┌─────┬─────┬─────┬─────┬ ... ┬─────┐
  0°  │ 3.2 │ 3.2 │ 3.3 │ NaN │     │ 5.1 │   row 0  (수평)
 -1°  │ 3.2 │ 3.2 │ 3.3 │ 3.4 │     │ 5.1 │
  ⋮   │     │     │     │     │     │     │
-90°  │ 2.4 │ NaN │ NaN │ NaN │     │ NaN │   row 90 (바닥=극점)
      └─────┴─────┴─────┴─────┴ ... ┴─────┘
        col 0  col 1 ...                col 359
```

### 4.3 격자를 쓰는 이유 세 가지

1. **중복 없이 organized로 내려면 셀 단위 배치가 필요하다.** 스트리밍으로 append하면 같은
   방향의 점이 여러 개 들어가 소비자가 어느 것이 진짜인지 모른다.
2. **미측정 셀을 "구멍"이 아니라 null/NaN으로 명시할 수 있다.** 캘리브 쪽이 "벽이 없어서
   안 잡힌 것"과 "측정에 실패한 것"을 구분해야 하는데, 점 목록만으로는 불가능하다.
3. **PCD도 organized(WIDTH=열, HEIGHT=행)가 되어** 2D 이미지처럼 이웃 관계가 살아난다.
   에지 검출·평면 분할이 훨씬 쉬워진다.

### 4.4 표준 스캔의 격자 크기 *(원본 = step 10 기준. 현행은 step 9 / 101×400)*

| 항목 | 값 |
|---|---|
| 요청 (기구각) | 팬 0~179°, 틸트 −90~+90°, 스텝 1° |
| 팬 줄 수 | 180줄 |
| 격자 (계약각) | **91행 × 360열 = 32,760셀** |
| 배치되는 점 | 32,580 |
| 빈 셀 | 180 (nadir 행의 극점 축퇴분, 정상) |
| 메모리 | 40B × 32,760 = **1.25 MB** |

### 4.5 nadir 행이 절반만 차는 이유

계약 tilt=−90(바닥)은 구면의 **극점**이라 방위가 축퇴한다. 모든 팬 줄이 같은 물리적
방향을 보므로 360개 방위 셀 중 180개만 채워진다. 버그가 아니라 구면 격자의 성질이다.

### 4.6 팬 이음매 — 0~180이 아니라 0~179인 이유

2축 스윕은 한 줄이 방위 *p*와 *p+180*을 함께 훑는다. 그래서 팬을 **0~180 양끝 포함**으로
돌리면 첫 줄과 마지막 줄이 **같은 수직 평면**을 잡는다.

전수 시뮬레이션 실측:

```
팬 0~180 (양끝 포함)   팬줄=181  점=32761  배치=32581  중복=180
팬 0~179 (끝 하나 제외) 팬줄=180  점=32580  배치=32580  중복=  0
```

데몬이 이 조건을 감지하면 스캔 시작 시 경고를 남긴다 (`scan_warn_seam()`).

## 5. 모터 제어

### 5.1 스텝각

| 항목 | 값 |
|---|---|
| 모터 기본 스텝각 | 1.8° |
| 마이크로스텝 (DRV8825 물리 스위치) | 1/16 |
| **1펄스당 각도** | **1.8 / 16 = 0.1125° = 1.125 ddeg** |
| 한 바퀴 | 3,200 펄스 |

### 5.2 타이머 → 펄스 속도

시스템 클럭 84MHz. TIM1은 APB2(84MHz), TIM2는 APB1×2(84MHz)로 둘 다 84MHz가 기준이다.

**인터럽트 1회당 최대 1펄스**이므로 타이머 주파수가 곧 최대 pps다. 목표에 도달했으면
펄스를 내지 않는다.

> ⚠️ 원본의 표(Pan 400Hz/45°/s, Tilt 800Hz/90°/s)는 현행과 다르다. 현재 코드는
> **Pan 100Hz(11.25°/s) / Tilt 400Hz(45°/s)** 이고, 가감속 램프가 ARR을 펄스마다 다시
> 쓰므로 CubeMX가 넣어둔 Period 값 자체는 램프 계층이 덮어쓴다.

### 5.3 ISR이 하는 일 — 펄스 하나뿐

```c
/* App/motor/motor.c : axis_step() — TIM ISR에서 호출 */
if (cur != tgt) {
    forward = (cur < tgt);
    HAL_GPIO_WritePin(DIR, forward ? dir_forward : 반대);
    for (i=0; i<MOTOR_DIR_SETUP_SPIN; i++) { }   /* 650ns 셋업 확보 */
    HAL_GPIO_WritePin(STEP, SET);
    for (i=0; i<MOTOR_STEP_PULSE_SPIN; i++) { }  /* 1.9us 이상 (~4us) */
    HAL_GPIO_WritePin(STEP, RESET);
    pulse = forward ? cur+1 : cur-1;
}
```

**ISR 안에서 하지 않는 것**: 분기하는 상태머신, printf, I2C, HAL_Delay. 전부 App/scan이
메인루프에서 한다.

**펄스 폭 5000 → 50 (약 0.42ms → 4µs).** 이전 구현은 ISR 안에서 0.42ms를 스핀했다. 틸트
ISR 주기가 1.25ms이므로 CPU의 3분의 1을 ISR에서 태우고, 그동안 라이다 UART(USART6) 수신
인터럽트가 밀려 프레임을 잃는다. DRV8825 요구치는 1.9µs라 4µs면 2배 여유다.
ISR 부하: 800Hz × 5µs = **0.4% CPU** (이전 33.6%).

### 5.4 각도 ↔ 펄스 변환과 절삭 누적

1펄스 = 1.125 ddeg이므로 `pulse = ddeg × 8/9`. 정수 연산이라 나머지가 버려진다. 틸트는
부호가 있으므로 0 방향 절삭이 아니라 **부호를 보존해 반올림**한다.

```c
static inline int32_t motor_ddeg_to_pulse(int32_t ddeg)
{
    return (ddeg >= 0) ? (((ddeg * 8) + 4) / 9)
                       : -((((-ddeg) * 8) + 4) / 9);
}
```

**절대각 전용이다. 증분에 쓰면 안 된다.** 1°(=10 ddeg) 스텝을 미리 펄스로 굳히면
9펄스(1.0125°)로 고정되어 180줄 누적 시 어긋난다. 목표는 매번 `start + line × step`을
통째로 환산해야 한다.

```
증분 누적 방식 : 1611 pulse -> 181.24도      ← 어긋남
절대각 방식    : 1591 pulse -> 178.99도      ← 목표 179.00도
```

### 5.5 상태 소유와 원자성

| 변수 | 쓰는 쪽 | 읽는 쪽 | 동기화 |
|---|---|---|---|
| `pulse` | TIM ISR | 메인루프 | 32비트 정렬 워드 → Cortex-M4에서 원자적 |
| `target` | 메인루프 | TIM ISR | 동일 (방향이 반대인 SPSC) |

예외는 `motor_sync_pulse()` 하나다. 양쪽이 같은 변수를 건드리므로 `__disable_irq()`로 잠깐
막는다. 이 함수는 **위치와 목표를 함께** 옮긴다 — 위치만 재영점하고 목표를 두면 다음
ISR이 옛 목표로 달려나간다.

`motor_disarm()`도 **목표를 현재 위치로 당긴 뒤** 전류를 끊는다. 순서가 반대면 다시
enable되는 순간 축이 튄다.

## 6. 라이다 측정

### 6.1 TOFSense-F2P NLink Frame0 (16바이트)

| 오프셋 | 필드 | 크기 | 내용 |
|---|---|---|---|
| 0 | header | 1 | 0x57 |
| 1 | function mark | 1 | 0x00 |
| 2 | reserved | 1 | — |
| 3 | id | 1 | — |
| 4~7 | system time | u32 LE | 라이다 자체 시계(ms) |
| 8~10 | distance | u24 LE | mm |
| 11 | distance status | 1 | **1=valid, 0=invalid** |
| 12~13 | signal strength | u16 LE | 정규화 안 된 원본 |
| 14 | range precision | 1 | F2P는 미지원 (0xFF 고정) |
| 15 | checksum | 1 | [0..14] 합의 하위 8비트 |

**dis_status 의미 확정**: 데이터시트는 1=valid, 매뉴얼 예제는 반대로 적혀 있다. 1축 브링업
실측에서 유효점 **359/359가 전부 1**이었으므로 데이터시트가 맞다.

### 6.2 각도-거리 동기 — 이 설계의 핵심

**폴링으로는 안 된다.** 메인루프가 언제 읽느냐에 따라 최대 한 프레임 주기(10ms) 어긋나는데,
틸트가 도는 동안 그 사이 격자 간격만큼 움직인다. 스미어가 격자와 맞먹으면 쓸 수 없다.

그래서 **16바이트가 완성된 그 순간** ISR에서 모터 각도를 함께 잡는다:

```
USART6 RX ISR ─ 1바이트씩 상태머신 ─ 16바이트 완성
                      │
                      ├─ scan_latch_angles()   pan/tilt 스냅샷 (ISR 안전)
                      └─ SPSC 링버퍼에 push
                                │
메인루프 lidar_process() ───────┴─ pop ─ scan_submit_sample() ─ uart_rpi_send_scan_point()
```

이렇게 하면 **각도-거리 짝짓기가 STM32 안에서 원자적으로 끝나**, RPi로는 이미 짝지어진
(pan, tilt, d)가 올라간다.

**링버퍼 깊이 8**: 라이다 100Hz(10ms)이고 메인루프의 가장 느린 구간이 프레임 상행(23바이트
≈ 2ms)이라 보통 한 칸을 넘지 않는다. 꽉 차면 **가장 오래된 것을 밀어내지 않고 새 것을
버린다** — 이미 들어간 샘플은 각도가 짝지어져 있어 순서를 흐트러뜨리면 데몬이 더 헷갈린다.

### 6.3 파서는 거르지 않는다

파서는 **체크섬만** 본다. 거리 범위·dis_status·신호세기로 점을 버리지 않고 원본 그대로
올린다.

**이유**: 판정 기준이 바뀌면 이미 찍어둔 스캔을 다시 해석할 수 있어야 한다. 펌웨어가 미리
버리면 그 점은 영영 복구되지 않는다. 실제로 1축 브링업에서 거리 상한 필터(10m) 때문에 먼
벽이 잘려나간 적이 있고, 그 상한도 F2P 사양(25m)과 맞지 않았다.

## 7. 엔코더 운용

### 7.1 왜 스윕 중에 안 읽는가

두 축 모두 **각도원은 스텝카운트**다. I2C 판독이 끝난 시각과 라이다 샘플 시각이 달라
오히려 동기 오차가 생기기 때문이다. 스텝카운트는 ISR에서 원자적으로 잡히므로 동기가
정확하다.

### 7.2 엔코더를 쓰는 세 곳

| 시점 | 동작 | 이유 |
|---|---|---|
| **① 홈 확립** | 양축 판독 1회 → 절대 위치 확정 | 절대 엔코더라 **구동이 필요 없다** |
| **② 틸트 줄 끝(±90)** | 스텝카운트와 대조 → 재영점 | 방향 전환이 탈조가 나는 자리 |
| **③ 팬 줄 시작** | 대조 후 **기록만** (보정 안 함) | §7.3 |

### 7.3 팬은 왜 보정하지 않고 검증만 하는가

팬이 정지 상태에서 1°(=9펄스)를 저속으로 가는 것은 탈조 위험이 사실상 없다. 관측된 탈조는
**빠른 축이 방향을 뒤집을 때** 났다 — 완전히 다른 영역이다.

게다가 폐루프 보정은 **새 실패 모드를 만든다**. 엔코더 잡음으로 오차를 잘못 읽으면 보정
이동이 들어가고, 그 이동 자체가 탈조를 일으킬 수 있다. 안 틀어진 것을 고치려다 틀어진다.

### 7.4 임계값

```c
#define SCAN_RESYNC_DDEG      3     /* 0.3도 초과 → 재영점        */
#define SCAN_STALL_DDEG      20     /* 2.0도 초과 → ERR_STALL     */
```

MT6701 분해능이 0.022°이고 1스텝이 0.1125°이므로, 0.3°(약 3스텝)면 측정 잡음이 아니라
실제 탈조로 볼 수 있다. 스텝당 엔코더 카운트가 5.12개라 **1스텝 탈조도 검출 가능**하다.

### 7.5 영점 상수

리밋스위치를 쓰지 않으므로 **양축 모두 벤치 캘리브 상수에 의존**한다.

```c
#define MOTOR_PAN_ZERO_OFFSET_DEG    225.31f   /* 실측 완료 */
#define MOTOR_TILT_ZERO_OFFSET_DEG   123.40f
```

**측정 절차**: ① 축을 기준 자세로 맞춘다(팬=기준 방위 / 틸트=바닥 nadir) ② `CMD_HOME`을
걸고 `turret_test state`가 찍는 엔코더 raw를 읽는다 ③ 그 값을 상수에 넣는다.

상수가 틀려도 `CMD_HOMED`가 raw를 함께 올리므로 **이미 찍은 스캔의 각도를 오프라인에서
재계산**할 수 있다(재스캔 불필요). "펌웨어를 안 건드렸는데 좌표가 통째로 틀어짐" 증상이
나오면 제일 먼저 의심할 곳이다.

### 9.1 STM32 메인루프

```c
while (1) {
    uart_rpi_process();      /* 링버퍼 파싱/디스패치        */
    lidar_process();         /* 라이다 샘플 큐 → scan 제출  */
    scan_process();          /* 스캔 시퀀서 (홈/스윕/대조)  */
    HAL_IWDG_Refresh(&hiwdg);

```

인터럽트는 세 종류만 돈다: TIM1/TIM2(스텝 펄스), USART1 RX(RPi), USART6 RX(라이다).

### 9.2 RPi 데몬 이벤트 루프

```c
epoll_wait()

  ├─ turret_fd (POLLIN)→ core_on_turret_event()  스캔점 drain + 상태 갱신
  ├─ signal_fd         → SIGTERM/SIGINT graceful shutdown
  └─ module fd         → 각 모듈 on_event
```

**단일 스레드라 락이 없다.** 모듈 간 데이터 교환은 코어가 들고 있는 `shared_ctx`를
통해서만 이루어진다.

## 10. 동작 시퀀스

### 10.1 부팅

STM32는 HAL/클럭/페리페럴 초기화 → USART1 수신 시작 → **축을 전류 차단 상태로 시작** →
스캔 시퀀서 초기화 → USART6 수신 시작 → TIM 인터럽트 시작 → 메인루프 진입.
**홈/스캔은 걸지 않는다 — 명령을 기다린다.**

RPi는 오버레이 + `insmod turret_driver.ko` → `/dev/turret` 생성 → 데몬 기동
(epoll/timerfd/signalfd 생성, 디바이스 open, 모듈 등록). `/dev/turret`이 없으면
**degraded 모드**로 계속 구동한다(개발 PC 대응).

### 10.2 Heartbeat (상시, 100ms 주기)

```
데몬 timerfd(100ms) → core_tick() → core_poll_link()
   │
   ├─ ioctl(TURRET_PING)  ──► 드라이버 ──► STM32 ──► CMD_PONG
   ├─ ioctl(TURRET_GET_STATE) ◄── 드라이버 RX콜백: pong_seq++
   └─ pong_seq 가 증가했으면 자기 CLOCK_MONOTONIC 으로 스탬프
      300ms 무응답 → link_dead 판정 → ST_DISARM 전이
```

**판정은 데몬이, 감지만 드라이버가.** 커널은 link_dead 타이머를 돌리지 않고 `pong_seq`
카운터만 증가시킨다(얇은 드라이버 원칙). 최후 안전망은 STM32의 IWDG(1.25초)다.

### 10.3 홈 확립 (CMD_HOME)

1. 데몬 `ioctl(TURRET_HOME)` → 드라이버가 프레임 조립 + CRC → UART TX (fire-and-forget)
2. STM32 ISR이 바이트를 링버퍼(256B)에 적재
3. 메인루프가 프레임 상태머신 → CRC 검증 → 디스패치
4. **여기서 엔코더를 읽지 않는다** — 상태만 SC_HOMING으로 바꾼다
5. 메인루프에서 양축 엔코더 판독 (블로킹 I2C라 메인루프에서만 안전)
6. 실측각 → 펄스 환산(영점 상수 적용) → `motor_sync_pulse()`로 위치·목표 동시 확정
7. `CMD_HOMED` 상행 — 엔코더 raw 2개 + 각도 2개
8. 드라이버가 캐시하고 STF_HOMED 세움 → 데몬이 `GET_STATE`로 회수해 산출물 provenance로 보관

판독 실패 시 `ERR_NOT_HOMED`를 올린다 — 조용히 넘기면 위치가 0에 머물고 목표(0)와 우연히
일치해 "축이 안 움직였는데 홈 완료"가 된다.

> ⚠️ 현행은 여기에 더해 **양축을 홈 자세로 이동**시키고 오차 0.3° 초과 시 최대 10회
> 세부조정한다. 최악 팬 180° 이동(≈8초) + 정착(3초).

### 10.4 스캔 시퀀서 상태 전이

```
   SC_IDLE
      │ CMD_SCAN_START
      ▼
   SC_MOVE_START ──── 양축 idle ────► SC_SWEEP ◄──────────────┐
      (시작점 이동)                       │                    │
                                    틸트 idle                  │
                                          ▼                    │
                                    SC_LINE_END                │
                                    · 틸트 엔코더 대조         │
                                    · 0.3° 초과 → 재영점       │
                                    · 2.0° 초과 → ERR_STALL    │
                                    · line++                   │
                                          │                    │
                             line < n_lines?                   │
                              ├─ 예 ──► SC_PAN_STEP ───────────┘
                              │         · 팬 목표 = 절대각 환산
                              │         · serpentine 반전
                              └─ 아니오 ──► SC_DONE
                                            · CMD_SCAN_DONE 상행
                                            · 팬만 시작점으로 복귀
```

**SC_SWEEP 구간의 점만 올린다.** 줄 끝 정지·팬 이동 중의 점은 격자에 넣을 각도가 아니다 —
같은 셀에 몰려 중복만 만든다.

### 10.5 라이다 샘플 1개의 전체 여정 (end-to-end)

```
 ① 라이다가 10ms마다 16바이트 프레임 송출 (USART6, 115200)
 ② STM32 USART6 RX ISR — 1바이트씩 상태머신   lidar_on_rx_cplt()
 ③ 16바이트 완성 → 체크섬 검증 + 필드 추출    lidar_parser_parse()
 ④ 그 순간의 모터 각도 래치            ★ 동기의 핵심   scan_latch_angles()
 ⑤ SPSC 링버퍼에 push (깊이 8)                lidar_push_sample()
 ─────────────────────── ISR 끝 / 메인루프 시작 ───────────────────────
 ⑥ 큐 pop                                     lidar_process()
 ⑦ 스캔 중(SC_SWEEP)인지 확인                 scan_submit_sample()
 ⑧ proto_scan_point(18B) 조립 + CRC → 23B 프레임 TX
 ─────────────────────── UART 115200 / RPi ───────────────────────
 ⑨ 커널 serdev RX 콜백 — SOF 탐색 → LEN 검사(CWE-120) → CRC 검증
 ⑩ CMD_SCAN_DATA → kfifo push (깊이 1024 = 10초치), poll 대기자 깨움
 ⑪ 데몬 epoll POLLIN → 배치 read (최대 64점)
 ⑫ 기구각 → 계약각 변환                       mech_to_contract()
 ⑬ 격자 좌표 계산 (반올림, 랩어라운드, 범위 검사)
 ⑭ 셀에 배치 (병합 규칙은 산출물 포맷 문서 §2.4)
 ⑮ 스캔 종료 시 파일 산출 — JSON(원시) + PCD(변환본)
```

### 10.6 중단 / 안전정지

| 명령 | STM32 동작 | 데몬 동작 |
|---|---|---|
| **SCAN_STOP** | 현재 위치를 목표로 당겨 정지 → SC_DONE으로 넘어가 `CMD_SCAN_DONE`은 **보낸다** | 여기까지 받은 점으로 파일 마감 |
| **DISARM** | `scan_stop()`으로 시퀀스 먼저 중단 → `motor_disarm()`으로 전류 차단 | ST_DISARM 전이 |

중단이어도 `CMD_SCAN_DONE`을 보내는 이유: 데몬이 `point_count`로 실제 받은 점 수를
대조하므로, 통지가 있어야 "몇 점에서 끊겼는지"를 알 수 있다.

### 10.7 에러 경로

| 코드 | 발생 조건 | 데몬 반응 |
|---|---|---|
| `ERR_NOT_HOMED` | 홈 전에 SCAN_START / 홈 시 엔코더 판독 실패 | 로그 + ST_DISARM |
| `ERR_OUT_OF_RANGE` | 스캔 범위·격자가 유효 범위 밖 | 동일 |
| `ERR_STALL` | 엔코더 대조 오차 2.0° 초과 | 스캔 중이면 ST_DISARM |
| CRC 불일치 | 프레임 손상 | 양단 파서가 폐기 후 재동기화 |
| link_dead | PONG 300ms 무응답 | ST_DISARM |
| IWDG 리셋 | 메인루프 1.25초 정지 | 재부팅 → 재홈 필요 |

전체 코드표는 → MQTT 토픽 계약 §3.5

## 11. 타이밍 · 자원 예산 *(원본 = step 10 / 틸트 800pps 기준)*

| 전체 스윕 | 180줄 × 2.00초 | **6.0 분** |

| 항목 | 값 |
|---|---|

## 12. 설계 결정과 근거

| 결정 | 근거 |
|---|---|
| **스캔 시퀀서를 ISR에서 메인루프로 분리** | 이전 구현은 시퀀서가 TIM ISR 안에 있어 `HAL_Delay`(SysTick 대기 → 데드락), `printf`·블로킹 I2C(라이다 프레임 유실)를 ISR에서 하게 됐다. 계층을 나누면 이 부류가 구조적으로 발생할 수 없다 |
| **틸트=빠른 축, 팬=느린 축** | 팬이 180°만 돌아 라이다 케이블이 감기지 않는다. 되감기 시퀀스가 불필요해진다 |
| **serpentine (줄마다 틸트 반전)** | 줄 끝에서 원위치로 되돌아가는 시간(줄당 2초 × 180 = 6분)을 없앤다 |
| **각도원 = 스텝카운트** | ISR에서 원자적으로 잡히므로 라이다 샘플과 시간축이 맞는다 |
| **팬 엔코더는 검증만, 보정 안 함** | 폐루프 보정이 새 실패 모드(잡음 → 불필요한 보정 이동 → 탈조)를 만든다 |
| **리밋스위치 미사용** | 절대 엔코더라 홈이 구동 없이 읽기 1회로 끝난다 |
| **파서가 거르지 않음** | 판정 기준이 바뀌어도 이미 찍은 스캔을 재해석할 수 있어야 한다 |
| **엔코더 raw를 CMD_HOMED에 실음** | 영점 상수가 틀려도 재스캔 없이 각도를 재계산할 수 있는 유일한 경로 |
| **기구각/계약각 분리** | 펌웨어가 좌표계를 몰라도 되고, 좌표 규약 변경이 데몬 한 함수로 국소화된다 |
| **격자 = 빔 FOV 기준** | 더 잘게 쪼개면 인접 측정이 물리적으로 같은 영역을 본다 |
| **데몬 = C11 단일스레드 epoll** | 드라이버(C)·STM32(C)와 한 멘탈모델. 락이 없어 경합 버그가 원천 차단 |
| **드라이버는 얇게** | heartbeat 판정·좌표 변환을 커널에 넣지 않는다 |
