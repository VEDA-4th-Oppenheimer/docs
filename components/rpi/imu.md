# IMU (ICM-20948) — 수평 기준

킷이 수평으로 거치되었는지 판정하는 경로 전체를 정리한 문서입니다. **MPU-6050에서
ICM-20948로 교체된 이후 기준**이며, 교체로 무엇이 바뀌고 무엇이 그대로인지를 2절에
따로 정리했습니다.

## 1. 구성

| 계층 | 파일 | 역할 |
|---|---|---|
| DT 오버레이 | `driver/overlays/imu-overlay.dts` | I2C1에 `imu@69` 노드 선언 |
| 커널 드라이버 | `driver/imu_driver.c` | ICM-20948 초기화 + `/dev/imu` 캐릭터 디바이스 |
| 테스트 앱 | `driver/imu_test.c` | 실시간 roll/pitch 표시, 영점 캘리브레이션 |
| 데몬 모듈 | `daemon/modules/imu/imu_module.c` | 1Hz 폴링 → roll/pitch 산출 → `ctx->level` |
| 판정 | `daemon/core` (`level_gate_ok`) | 임계 초과면 `SCANNING` 진입 거부 |
| 발행 | `daemon/modules/mqtt` | `adts/state/daemon` 의 `level` 블록 |

**역할은 "게이트"입니다(방식 A).** 기울기를 측정해 **스캔 진입을 막을 뿐**, 좌표를
회전 보정하지 않습니다. 향후 보정(방식 B)으로 확장할 때를 대비해 원본 각도를
`raw_roll_deg` / `raw_pitch_deg` 로 함께 남깁니다.

자력계는 쓰지 않습니다 — MT6701이 자기식 엔코더라 축마다 자석이 붙어 있고 스텝모터
코일도 바로 옆이라 방위 측정이 의미가 없습니다.

## 2. MPU-6050 → ICM-20948 교체 (2026-08-13, `57d1f0b`)

### 그대로인 것

**배선(SDA/SCL/GND/VCC)과 `/dev/imu` 계약이 유지됩니다.** 그래서 `imu_module.c` 와
`imu_test.c` 의 파싱 코드는 **한 줄도 바뀌지 않았습니다.** ICM-20948도 바이트 순서와
폭이 같고, 드라이버가 레인지를 ±2g로 잡아 16384 LSB/g로 스케일까지 동일하기 때문입니다.

### 바뀐 것

| 항목 | MPU-6050 | ICM-20948 |
|---|---|---|
| **슬레이브 주소** | 0x68 (GY-521은 AD0=L) | **0x69** (이 브레이크아웃은 AD0=H) |
| 레지스터 구성 | 평면 | **4개 뱅크** — `REG_BANK_SEL(0x7F)` 로 전환 |
| `PWR_MGMT_1` | 0x6B | 0x06 (뱅크0) |
| 가속도 시작 | 0x3B | 0x2D (뱅크0) |
| WHO_AM_I | 0x68 | **0xEA** (0x00, 뱅크0) |
| 리셋 직후 전원 | SLEEP만 | SLEEP + **LP_EN** (0x41) |
| 가속도 DLPF | 미사용 | **5.7Hz 활성** |
| DT compatible | `adts,imu-mpu6050` | `adts,imu-icm20948` |

> **주소 0x69가 가장 걸리기 쉬운 지점입니다.** 배선을 그대로 꽂아도 주소가 달라집니다.
> 증상은 "probe는 붙는데 read가 전부 `-EIO`" 이거나, DT 노드가 안 맞으면 **아무 로그도
> 안 뜹니다.** `i2cdetect -y 1` 로 실측 확인하십시오.
>
> 참고: 드라이버 `icm20948_setup()` 의 WHO_AM_I 단계 주석에 "주소도 0x68로 같아서"라는
> 문장이 남아 있는데, 이는 교체 전 문구가 남은 것입니다. 실제 주소는 0x69입니다
> (`dbe4a45` 에서 정정).

### 교체하며 함께 고친 것

- **LP_EN 해제**: SLEEP만 풀고 LP_EN을 남기면 샘플이 띄엄띄엄 갱신돼 **"값이 멈춘 것처럼"**
  보입니다. `PWR_MGMT_1 = 0x01` 로 둘 다 풀고 CLKSEL=1(자동)을 씁니다.
- **가속도 DLPF 5.7Hz**: IMU가 스텝모터 바로 옆이고 마운트가 한쪽만 지지된 상태라 진동이
  그대로 들어옵니다. 수평 게이트는 1Hz 판정이라 대역폭이 남아돌아 세게 거는 편이 이득입니다.
- **probe 레이스 수정**: `imu_client` 를 초기화가 **끝난 뒤에** 공개합니다. 종전에는 진입
  직후 공개해서 리셋~웨이크 150ms 동안 read가 초기화 중인 칩을 읽었고, ICM-20948에서는
  그 구간에 **뱅크가 2인 때**가 있어 가속도 대신 설정 레지스터를 읽어 갑니다.

## 3. `/dev/imu` 계약

```c
read(fd, buf, 6)   /* 뱅크0 레지스터 0x2D(ACCEL_XOUT_H)부터 원본 그대로 */
```

- `buf[0..1]=ax`, `buf[2..3]=ay`, `buf[4..5]=az` — 각각 **빅엔디안 int16**
- 스케일 **16384 LSB/g** (±2g)
- `len < 6` → `-EINVAL` / 드라이버는 떴는데 칩이 없음 → `-ENODEV`, `-EIO`
- `noop_llseek` — 스트림 디바이스라 seek 무의미

각도 산출식은 드라이버 사용자(데몬·테스트앱)가 동일하게 씁니다.

```
roll  = atan2(ay, az)
pitch = atan2(-ax, sqrt(ay² + az²))
```

> `atan2` 는 비율만 쓰므로 스케일이 결과를 바꾸지 않습니다. 그래도 두 프로그램이 같은
> 상수를 쓰는 이유는, 숫자가 어긋나면 "어느 쪽이 맞나"를 매번 따지게 되기 때문입니다.
> 드라이버에서 `FS_SEL` 을 바꾸면 데몬의 `IMU_ACCEL_LSB_PER_G` 도 반드시 같이 고쳐야
> 합니다 — 두 곳이 어긋나면 각도가 아니라 **스케일만 틀려서 잘 드러나지 않습니다.**

## 4. 커널 드라이버 (`driver/imu_driver.c`)

### 레지스터 뱅크

ICM-20948은 레지스터가 4개 뱅크로 나뉘고 `REG_BANK_SEL(0x7F)` 만 **모든 뱅크에서**
보입니다. 설정은 뱅크2, 데이터/전원은 뱅크0이라 probe가 뱅크를 오갑니다.

> **probe는 반드시 뱅크0으로 되돌려놓고 끝나야 합니다.** `imu_read()` 가 뱅크0(0x2D)을
> 읽고, 런타임에 뱅크를 바꾸는 경로가 없다는 전제로 **매 read마다 뱅크를 다시 고르지
> 않기** 때문입니다. 나중에 자이로/자력계 설정을 런타임에 바꾸는 코드를 넣는다면, 그
> 경로가 뱅크0으로 복구하거나 read에서 매번 선택해야 합니다.

`icm20948_set_bank()` 의 반환값을 반드시 확인하는 이유도 같습니다 — 실패를 넘기면
**엉뚱한 뱅크의 같은 주소**에 쓰게 되어 조용히 다른 레지스터를 망가뜨립니다.

### 초기화 순서 (`icm20948_setup`)

| 단계 | 내용 | 실패 시 |
|---|---|---|
| 1 | 뱅크0 선택 → `DEVICE_RESET` → 100ms 대기 | 반환값 안 봄(리셋 중 무응답 가능) |
| 2 | 뱅크0 재선택 | I2C 배선/주소 문제로 보고 |
| 3 | **WHO_AM_I == 0xEA** 확인 | `-ENODEV` |
| 4 | `PWR_MGMT_1 = 0x01` (SLEEP·LP_EN 해제) → 50ms | 반환 |
| 5 | `PWR_MGMT_2 = 0x00` (가속도·자이로 전원) | 반환 |
| 6 | 뱅크2 → `ACCEL_CONFIG = 0x31` (±2g, DLPF 5.7Hz) | **뱅크0 복구 후** 반환 |
| 7 | 뱅크0 복귀 → 50ms(DLPF 채움) | 반환 |

**WHO_AM_I 검사가 유일한 방어선입니다.** 배선이 같아 물리적으로는 아무 칩이나 꽂히고,
검사가 없으면 엉뚱한 칩이어도 아무 증상 없이 통과합니다(MPU-6050이면 0x68이 나옵니다).

### 그 밖에 주의할 구현

- **`i2c_transfer` 는 전송한 메시지 수를 돌려줍니다.** 성공이면 반드시 2입니다.
  `ret < 0` 만 보면 부분 전송(주소 ACK는 받았지만 데이터 단계에서 끊김)을 성공으로 읽어
  **채워지지 않은 버퍼의 쓰레기 값**을 가속도로 쓰게 됩니다. 수평 게이트가 그 값으로
  판정하므로 조용히 틀린 답이 나옵니다. 그래서 `ret == 2` 를 명시적으로 확인합니다.
- **DT 바인딩과 이름 충돌**: `compatible` 에 표준 문자열(`invensense,icm20948`)을 쓰지
  않습니다. 커널 내장 `inv-mpu6050` 계열이 ICM-20948도 물고 있어 바인딩이 경합합니다.
  같은 이유로 `driver.name` 을 `imu_icm20948_custom` 으로 둡니다 — 겹치면
  `i2c_add_driver()` 가 "already registered"로 실패합니다.
- **오버레이와 `of_match_table` 은 짝입니다.** 한쪽만 바꾸면 probe가 붙지 않습니다.
  오버레이만 올리고 드라이버에 매칭이 없으면 아무 일도 안 일어나고, 반대면 붙을 노드가
  없습니다.
- **`/dev/imu` 는 0666** (`imu_devnode` 콜백). turret은 miscdevice라 `.mode` 한 줄이면
  되지만 여기는 `class_create` + `device_create` 방식이라 클래스에 콜백을 답니다. 콜백은
  **`device_create` 전에** 달아야 합니다 — 노드는 그 시점에 만들어집니다.
- raw 덤프는 `pr_debug` 입니다(데몬이 1Hz로 계속 읽어 dmesg가 밀립니다). 필요할 때:
  `echo 'file imu_driver.c +p' > /sys/kernel/debug/dynamic_debug/control`

## 5. 데몬 모듈 (`daemon/modules/imu/imu_module.c`)

- **1Hz 폴링**입니다. `get_fd` 가 -1을 돌려 epoll에 등록하지 않습니다 — 드라이버가
  `poll()` 을 구현하지 않고, 사람이 수평을 맞추는 속도면 1Hz로 충분합니다.
- **`ST_SCANNING` 중에는 읽지 않습니다.** 판정은 진입 시점에 끝났고, `read()` 는 블로킹
  I2C라 단일스레드 epoll 루프가 I2C 왕복만큼 멈추면 **라이다 점 배치 수신이 밀립니다.**
- **열기 실패해도 `init` 은 성공(0)을 반환합니다.** IMU가 없다고 데몬 전체가 죽으면 개발이
  막히고, 코어는 `level.valid == 0` 을 "게이트 생략"으로 이미 처리합니다(경고 로그가 남음).
- **실패하면 `valid` 를 내립니다.** 낡은 값을 남겨두면 센서가 빠진 뒤에도 "수평 OK"로
  스캔이 통과해 게이트의 존재 이유가 사라집니다.
- **3축이 모두 0이면 무효 처리합니다.** 칩이 응답만 하고 값을 안 주는 상태(슬립 해제 실패
  등)인데, `atan2(0,0)` 이 0을 돌려주므로 그대로 두면 **"완벽한 수평"으로 보여 게이트를
  무사통과**합니다.
- **첫 측정은 raw와 보정 후 값을 둘 다 로그로 찍습니다.** 보정 후 값만 보이면 "센서가
  수평을 읽는다"와 "오프셋이 그만큼 빼주고 있다"를 구분할 수 없습니다.

`ctx->level` 에 채우는 값:

| 필드 | 의미 |
|---|---|
| `roll_deg` / `pitch_deg` | 설치각 오프셋을 뺀 값 = **기준 자세로부터의 이탈**. 게이트와 관제 표시가 둘 다 이것을 봅니다 |
| `raw_roll_deg` / `raw_pitch_deg` | 오프셋을 빼기 전 중력벡터 각. 방식 B는 "이탈"이 아니라 실제 기울기가 필요합니다 |
| `valid` | 1 = 최근 측정 유효 |

## 6. 수평 게이트와 설치각 오프셋 — **현재 상태 주의**

```c
#define LEVEL_GATE_MAX_DEG     10.0f   /* shared/daemon_module.h */
#define IMU_INSTALL_ROLL_DEG   -3.0f
#define IMU_INSTALL_PITCH_DEG   4.0f
```

> **지금 이 게이트는 사실상 아무것도 막지 않습니다.** 브링업 설정입니다.

이유가 두 겹입니다.

**① 임계값 10.0도에 근거가 없습니다.** 원래 6.0이었는데 "3.6도 기울어진 킷을 통과시키기
위해" 올린 값이었고, 이후 Pi 작업트리에서 이미 10.0으로 돌고 있어 레포를 실제 값에
맞췄습니다(2026-08-17). 6도/10도까지 허용해도 된다는 뜻이 아닙니다.

**② 설치각 오프셋이 "그때 자세"를 기준으로 선언되어 있습니다.** `IMU_INSTALL_*_DEG` 는
**"이 자세가 수평이다"라고 선언하는** 상수입니다. 현재 값은 수평기로 기구를 맞추는 단계를
**건너뛴 채** 그때 자세를 그대로 넣은 것입니다. 그래서 `level` 값은 0 근처로 나오지만 킷은
여전히 약 3.6도 기울어 있습니다 — 임계를 3.0으로 되돌려도 마찬가지입니다.

### 되돌리는 순서

1. **킷 거치 자세 교정** — IMU가 아니라 **바닥평면 기울기**를 보고 맞춥니다. 내리막 방위
   232도 쪽이 낮습니다(받침 지름 200mm 기준 심 약 12.6mm).
2. 수평기를 **팬축 마운트**에 대고 맞춘 뒤 `imu_test` 에서 `z`(20샘플 평균 영점)를 눌러
   찍힌 Roll/Pitch를 `IMU_INSTALL_*_DEG` 에 넣고 데몬을 다시 빌드합니다.
3. `LEVEL_GATE_MAX_DEG` 를 3.0 이하로 되돌립니다.

**이 세 단계 전까지 게이트 통과는 "수평이 확인됐다"는 뜻이 아닙니다.**

> 참고: 바닥평면으로 재는 방식이 IMU보다 정확합니다 — 편차 0.05도(6회 반복) 대 IMU 잡음
> 0.2~0.3도이고, 장착각이라는 미지수가 없습니다. 게이트는 "사람이 현장에서 대충 맞췄나"를
> 보는 용도로 두고, 산출물의 기울기 판정·보정은 바닥평면 기준이 낫습니다.

## 7. 브링업 · 진단 절차

```bash
sudo rmmod imu_driver
sudo insmod imu_driver.ko

# (권장) 오버레이로 붙이기
sudo dtoverlay overlays/imu-overlay.dtbo
# (임시) 손으로 붙이기 — 재부팅하면 사라짐
echo icm20948 0x69 | sudo tee /sys/bus/i2c/devices/i2c-1/new_device

i2cdetect -y 1        # 0x69 에 보여야 한다 (0x68 이면 AD0=L 보드)
dmesg | tail -n 10    # probe 성공 / WHO_AM_I 불일치가 여기서 잡힌다
./imu_test            # 실시간 roll/pitch, z=영점, r=오프셋 리셋
```

> **순서 주의**: DT 노드가 먼저 있어야 `insmod` 때 매칭됩니다. 오버레이를 나중에 올리면
> `compatible` 속성만 바뀔 뿐 **재매칭이 일어나지 않아** probe가 조용히 안 불립니다.
> `config.txt` 에 `dtoverlay=imu-overlay` 로 걸어두는 쪽이 확실합니다.

증상별 확인 순서:

| 증상 | 먼저 볼 것 |
|---|---|
| dmesg에 아무 로그도 없음 | DT 노드 미매칭 — 오버레이 `compatible` 과 드라이버 `of_match_table` |
| probe는 붙는데 read가 `-EIO` | 슬레이브 주소(0x69 vs 0x68) |
| WHO_AM_I 불일치 | 다른 칩이 꽂힘 (0x68이면 MPU-6050) |
| 값이 멈춘 것처럼 보임 | LP_EN 해제 실패 — `PWR_MGMT_1` 로그 |
| 3축 전부 0 | 초기화 실패. 데몬이 경고를 찍고 `valid=0` |
| 게이트가 갑자기 막거나 통과 | 리그 자세보다 **IMU 마운트**를 먼저 의심 (8절) |

## 8. 알려진 문제 · 미확인 항목

**① 실기 검증이 안 됐습니다.** 교체 커밋(`57d1f0b`) 시점에 커널 모듈 빌드도 dtc 컴파일도
개발 호스트(macOS)에서는 불가라 `imu_test.c` 의 호스트 컴파일만 확인했습니다.

**② 축 방향(roll/pitch 부호)이 미확인입니다.** 칩이 바뀌면서 패키지 축이나 브레이크아웃
실장 방향이 달라졌을 수 있어 **부호가 뒤집히거나 두 축이 서로 바뀔 수 있습니다.** 배선만
같다고 같은 각도가 나오지 않습니다. `imu_test` 로 앞뒤/좌우로 기울여 확인해야 하며,
`z`(영점)는 오프셋만 없애 줄 뿐 **부호는 고치지 못합니다.**

**③ IMU 마운트가 움직인 이력이 있습니다.** 브래킷 다리가 한쪽뿐이라, 같은 날 두 판독에서
roll이 **+4.08 → -3.05 (7.1도)** 튀었습니다(pitch는 +3.79 → +3.91로 거의 불변). 한 점
지지에서 남는 회전 자유도 하나와 정확히 맞는 패턴입니다. 현재 오프셋 상수는 **센서를
물리적으로 고정한 뒤** 잰 값을 전제로 합니다.

**④ MPU-6050 시절 실측값은 폐기됐습니다.** "IMU 1.1도 / 장착 2.7도 어긋남"은 교체로
보고값이 통째로 바뀌어 더 이상 유효하지 않습니다.
